# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PharmaLens (`pharmalens` package) is a Flutter app that reads prescriptions and acts as a medicine safety assistant for Lebanon. It targets Android, iOS, web and desktop, and supports English and Arabic (RTL). Made by TechWrap LB.

## Commands

```bash
setup.bat                                      # new computer: checks tools and Developer Mode, creates lib/private/*.dart from the templates (asks for keys), git hook, pub get
flutter pub get
flutter run                                    # dev; see "Secrets" for keys
flutter run --dart-define=GEMINI_API_KEY=...  # instead of lib/private/api_keys.dart (GEMINI_API_KEYS=a,b for several)
flutter run -d chrome --web-port=59115        # the port the VS Code launch config uses; tools/run_auto_reload.ps1 wraps this with hot reload on save
flutter analyze                                # flutter_lints is enabled; keep it at "No issues found"
flutter test
flutter test test/safety_logic_test.dart --plain-name "1000mg written matches a 1g product"
flutter gen-l10n                               # after editing lib/l10n/*.arb
python tools/update_moph_dataset.py           # fetch the newest MOPH sheet and rebuild the CSV if it changed (needs `pip install xlrd`; --force rebuilds anyway)
python tools/build_medicine_dataset.py --xls path/to/WebMarketed.xls   # rebuild the CSV from a sheet you already have; LNDI pages are cached in .moph_cache/
python tools/generate_brand_assets.py         # redraw the logo, every app icon and the in-app illustrations (needs Pillow)
```

- **Android:** Gradle 8.14 does not run on Java 25. Point Flutter at JDK 17 (`flutter config --jdk-dir=...`), or run `android/gradlew` with `JAVA_HOME` set to JDK 17.
- **Release signing:** `android/key.properties` (git-ignored) with `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. Without it, release builds use the debug key, which Google Play rejects. Never print or commit its values.
- **Google Play:** the package is `com.techwraplb.pharmalens`. It was `com.codepeakstudio.pharmalens` before the first Play upload and must never change again. Upload `flutter build appbundle --release`, and raise `version:` in pubspec.yaml plus `_appVersion` in settings_screen.dart for every upload.
  - [docs/play-store/README.md](docs/play-store/README.md) has every Play Console answer: Data safety, the health and full-screen-intent declarations, and the listing texts with the "not the MOPH app" disclaimer. Keep it true when features change (new data sent off the phone, new permissions).
  - Play policy features to keep: the privacy policy (`assets/legal/privacy_policy_{en,ar}.md`, shown in Settings; `python tools/build_privacy_page.py` rebuilds the techwraplb.com pages in `docs/web/pharmalens/`, live at `AppInfo.privacyPolicyUrl`; upload steps are in docs/play-store/README.md), "Report this answer" on assistant answers ([report_answer_sheet.dart](lib/widgets/report_answer_sheet.dart), required for generative AI), and "Delete all my data" ([user_data_service.dart](lib/services/user_data_service.dart)). New personal data must be added to `deleteAllUserData`. [test/play_store_test.dart](test/play_store_test.dart) covers them.
- **R8:** release builds shrink code and resources. Most plugins bring their own keep rules; `flutter_local_notifications` does not, and without the Gson keep rules in [proguard-rules.pro](android/app/proguard-rules.pro) it cannot read back its saved schedule after a reboot (reminders silently stopped after a restart). That file also silences ML Kit's optional scripts. Resources referenced only by name from Dart (notification icon `@mipmap/ic_launcher_monochrome`, `@raw/pharmalens_alarm`) must be listed in [keep.xml](android/app/src/main/res/raw/keep.xml) or they are stripped.
- **Windows desktop:** builds need Windows Developer Mode, for plugin symlinks.
- **Web links:** `/?tab=doctors` opens a section, and `/?tab=medicines&medicine=<MOPH code>` opens a medicine page. Both are handy for headless screenshots of `build/web`.

## Secrets

`lib/private/*.dart` is git-ignored. `setup.bat` (tools/setup.ps1) creates them from the committed `*.example.dart` templates; every VS Code launch runs `tools/setup.ps1 -Quick` first, so a fresh clone compiles with no keys (those features stay off). Keep the templates' placeholder lines in sync with the script's `Replace` calls. Run `git config core.hooksPath .githooks` once per clone: the pre-commit hook blocks any staged Google/Gemini key (the repo is public, and keys from early commits are still in its history, so any key that was ever committed must be rotated, not just removed). For CI or Play Store builds on another machine, pass keys with `--dart-define=GEMINI_API_KEY=...` instead of the file. Keys needed: Gemini (`api_keys.dart`) and Google Places (`google_maps_private_config.dart`, nearby places and hospital contacts). The keys ship inside the app, so restrict each in Google Cloud (API restriction plus a quota cap). Release keys can also be restricted to the Android app: every Gemini and Places call sends `X-Android-Package` and `X-Android-Cert` ([android_app_identity.dart](lib/services/android_app_identity.dart), read from the signing certificate in MainActivity). New Google API calls must add `AndroidAppIdentity.headers()` too. Model order (in `api_keys.dart`): `gemini-3.5-flash` first, then the Flash-Lite models. `GeminiClient` moves to the next key and model on HTTP 429, so the small free-tier Flash quota falls back to Flash-Lite. Free-tier quotas are per Cloud project, and Google's unpaid terms forbid sending personal or sensitive data, so production should use a billed key.
- Judge speed only on profile or release builds; debug builds took 8–10 s to open on a mid-range phone (TECNO LF7, MediaTek, OpenGL ES).
- Android renders with **Skia**, not Impeller (`EnableImpeller` = false in AndroidManifest.xml). On that phone Impeller drew the first frame at 2.15 s and missed 9% of frames scrolling home; Skia took 0.59 s and missed 1%. Flutter warns this opt-out is deprecated: re-measure before each Flutter upgrade with `flutter drive --profile -d <device> --driver=test_driver/perf_driver.dart --target=integration_test/scroll_perf_test.dart` (add `--no-enable-impeller` or `--enable-impeller` to compare). It uses FrameTiming callbacks, so it works over wireless ADB. `flutter run --profile --trace-startup` gives first-frame times. No Maps SDK key: the map does not use Google. Never print key values or commit them.

## Safety-critical code

Changes to these files need a test in [test/safety_logic_test.dart](test/safety_logic_test.dart) (or next to it), using the real bundled catalog where possible:
[medicine_equivalence.dart](lib/utils/medicine_equivalence.dart), [medicine_verification_service.dart](lib/services/medicine_verification_service.dart), [medication_safety_service.dart](lib/services/medication_safety_service.dart), [medical_domain_guard_service.dart](lib/services/medical_domain_guard_service.dart), [reminder_service.dart](lib/services/reminder_service.dart) and [medicine_reminder.dart](lib/models/medicine_reminder.dart).

To load the real catalog in a test, do what `safety_logic_test.dart` does in `setUpAll`: call `SharedPreferences.setMockInitialValues({})`, then `await MophMedicineService().initialize()`. The services are singletons, so state carries over between tests in the same file.

## Architecture

**Shell ([lib/app/app_shell.dart](lib/app/app_shell.dart)):** below 720 px, `_PhoneNavBar`: a flat bar in the theme's surface color (light or dark): Home, Medicines, a raised rounded-square Scan button in a halo of the bar's color, Pharmacies, My health. The halo is a plain Stack inside the bar's own height, so all of it can be tapped. Labels stay on one line (`FittedBox`, text scale clamped), because the old `NavigationBar` wrapped them on narrow phones. Doctors opens from the home tiles on phones.
- Keep the bar cheap. A notched `BottomAppBar` with a docked button was laid out again on every keyboard frame and made the app lag. Now the bar sits on its own `RepaintBoundary`, hides while the keyboard is open, and the shell `Scaffold` has `resizeToAvoidBottomInset: false`, so only the section's own `Scaffold` resizes. A `NavigationRail` is used up to 1100 px and a sidebar above that; both list every tab and have a Scan button. Breakpoints live in [lib/widgets/responsive.dart](lib/widgets/responsive.dart), alongside `PageFrame`, `AdaptiveGrid`, `SurfaceCard`, `AdaptiveBackButton`, `PressableScale`, `FadeSlideIn` and `GradientPageHeader` (the navy header of My Health, Doctors and Medicines).
- Each tab has its own `Navigator`, and tabs are built lazily on first visit. Pushed pages (analysis, medicine details) stay beside the sidebar on desktop.
- Switch sections through `AppShellScope.maybeOf(context)?.selectTab(...)`.
- On phones, Settings is pushed rather than shown as a tab.
- On each launch, after the first frame, the shell shows `showStartupNotice` ([official_notice.dart](lib/widgets/official_notice.dart)). It is the "AI can make mistakes" acknowledgement, or once, for people onboarded before it existed, the "individual initiative, not the MOPH app" notice. Onboarding shows that page itself and skips the launch notice. Widget tests that pump `AppShell` set `startupNoticeShown = true` and `OfficialNoticeCard.seenKey`, or the dialog covers the screen.
- Screens must work both as a tab root (no back button) and as a pushed page. Use `AdaptiveBackButton` or `Navigator.canPop`.
- The shell listens to `ReminderService().pendingDose` and opens the dose screen over everything; it also reports MOPH price changes for the user's own medicines.

**Startup ([lib/main.dart](lib/main.dart)):** there is no backend. `runApp` comes first; nothing heavy is awaited before the first frame. A branded startup screen matches the native splash, then first-run onboarding (privacy notice, reminder setup) or the shell.
- `MophMedicineService` parses its bundled CSV in a background isolate (`compute`) after the first frame. It never throws (see `loadError`). UI that shows counts or dates listens to `MophMedicineService().changes` (first load plus newer lists); code that needs the data awaits `initialize()`.
- `DoctorsService` (18,000 rows) is parsed five seconds after launch; the Doctors tab and the assistant await it.
- Connectivity, history, profiles then reminders, and the dose log load in the background.
- Flutter runs Dart on Android's UI thread, so main-isolate work and plugin calls before the first frame delay the app opening. Keep heavy work in isolates or after the first screen (the reminder schedule rebuild is deferred and skipped when unchanged; see Reminders). Home shows `MophSyncChip` at the top while the list loads or checks.

**Data: official sources only, never invented.**
- **Medicines:** `assets/medicines/lebanon_medicine_prices.csv` is generated by [tools/build_medicine_dataset.py](tools/build_medicine_dataset.py) from the MOPH Drugs Public Price List (XLS) joined with the Lebanon National Drug Index (ingredients, ATC).
  - Rows are keyed by MOPH code (`medicine_id`). List fields use `|`, and fields contain no newlines, because the CSV is parsed line by line. The `source`, `source_url` and `notes` columns were dropped (2026-10); the app fills the source link with `MophMedicineService.mophPublicUrl`.
  - `MophMedicineService` dedupes by code, so it keeps every strength and pack of a brand. It indexes products by code (`findById`) and normalizes search names once per product.
  - Search: scored on normalized brand, generic and ingredients; the last ranking is cached so paging does not re-score, and `countMatches` gives the total for labels. Text in Arabic letters ("بنادول") is matched by consonant skeleton ([phonetic_skeleton.dart](lib/utils/phonetic_skeleton.dart)).
  - **Automatic updates:** [.github/workflows/update-moph-prices.yml](.github/workflows/update-moph-prices.yml) runs [tools/update_moph_dataset.py](tools/update_moph_dataset.py) every 6 hours. MOPH names files by hand (`WebMarketed20261005-19-10-2026.xls`, `WebMarketed20261111-.xls`; a strict filename regex once missed a release for days while every run stayed green), so nothing may depend on one naming pattern:
    - `find_sheet` recognizes the price sheet by file name ("marketed", not "non marketed") or link text ("Drugs Public Price List"), and dates it by the newest date in its path in any common format, else the server's `Last-Modified`.
    - Whether to rebuild is decided by the sheet's content (`source_sha256` in the manifest), so a same-name re-upload is caught. `.xls` and `.xlsx` are both read, detected by file content.
    - The run fails (GitHub emails the maintainer) when the page announces a newer release (heading or dated folder) than the sheet found, or has an unclassifiable spreadsheet that may be newer. Never turn these failures into a quiet "up to date".
    - [tools/test_update_moph_dataset.py](tools/test_update_moph_dataset.py) covers the naming cases offline and runs before each update; add a case whenever MOPH surprises us.
    - The build is rejected when it looks broken (row drop, missing ingredients, or more than 15% of prices changing threefold; the workflow's `allow_price_jumps` input accepts a real mass repricing). Then the CSV is committed with `lebanon_medicine_prices.json`.
    - Manifest contract with installed apps (`MophDatasetManifest.isNewerThan`, tested in [moph_update_test.dart](test/moph_update_test.dart)): a later `published` wins; on the same date a different `version` with a later `generated_at` wins. The script never lowers `published` and puts the CSV hash in `version`. Apps already installed can't be changed, so keep any manifest change within this contract.
  - The app downloads from `MophMedicineService.dataBaseUrl` (raw GitHub by default; `--dart-define=MOPH_DATA_BASE_URL=`). `startAutoUpdates()` checks the manifest on every launch, then at most hourly on reconnect and app resume, and on Sync; the CSV is fetched only when the manifest is newer and must match its `sha256` and row count. Downloaded lists are saved to a file (browser storage on web), `datasetRevision` notifies the UI, and `lastPriceChanges` lists what changed. `progress` (stage plus 0..1) drives [sync_progress.dart](lib/widgets/sync_progress.dart): the home card, Settings and Medicines show "Checking for new data… 42%", and `MophSyncButton` can't be pressed again until `isSyncing` ends.
  - The app's base URL must be publicly readable. If the repo is private, set the workflow's `DATA_REPO` variable and `DATA_REPO_TOKEN` secret to mirror the files to a public repo, and point `MOPH_DATA_BASE_URL` there.
- **Equivalence:** [lib/utils/medicine_equivalence.dart](lib/utils/medicine_equivalence.dart) is the canonical definition of "same ingredient / strength / form" and of price per tablet, ml or g. Alternatives, the cheapest-equivalent list, verification and safety checks all build on it; `MedicineNormalizer` is for search text only.
  - Form families check the route first (eye, ear, nasal, inhalation, vaginal, rectal, injection) so a vaginal tablet never equals an oral one. Modified release is matched on whole words.
  - `strengthKey` turns g and mcg into mg; `packQuantity` reads "10x1ml" as 10 ml.
- **Doctors:** `assets/doctors/lebanon_doctors.csv` comes from the Lebanese Order of Physicians list. It has name, code, specialty and hospital only: no gender, phone or address.
  - Gender is estimated from the Arabic first name by [lib/utils/doctor_gender_resolver.dart](lib/utils/doctor_gender_resolver.dart), and `Doctor.genderEstimated` is set. Unisex names stay unknown.
  - Hospital phone and location are looked up at runtime through Google Places (`HospitalContactService`) and cached for 30 days.
- **Patient information** (uses, how to take, side effects, warnings): the MOPH list has none, so [lib/services/medicine_info_service.dart](lib/services/medicine_info_service.dart) builds it at runtime.
  - It takes the openFDA drug label with the same ingredients, route, form and (preferably) strength, maps INN names to US ones (`paracetamol` → `acetaminophen`), and has Gemini summarize it in English and Arabic. With no matching label, Gemini writes it from general knowledge.
  - The page always labels the origin (`MedicineInfoOrigin`): AI summary of an FDA label, raw FDA label (no Gemini key), or AI-written. Keep that label; never present this text as reviewed or official.
  - Doses are only stated for the product's own strength. Results are cached per ingredients + form family + strength, one file each under the app support directory (SharedPreferences only on web and in tests).
  - Don't put growing caches in SharedPreferences. Android reads the whole store before the first screen; this cache used to live there and made every launch slower. `dropCacheFromPreferences` clears the old entries 8 s after launch.
  - On a scanned medicine, "How to use" shows the doctor's written directions first; without them it says they could not be read and to ask, then the usual use. The scan prompt's DIRECTIONS section and schema descriptions make Gemini copy directions (often Arabic, on the line under the name) into `writtenInstructions`, dose, frequency and duration; without them it left these empty.
  - `ForYouCard` quotes the label lines that match the selected person's allergies and conditions, and their age (under 12 counts as "child"; 65 and over always gets a check-with-your-doctor note), weight (weight-based dosing, under 40 kg) and BMI (weight-loss medicines, ATC A08, with a normal BMI). It never says a medicine is safe. `LabelInteractionService` (on request, from the scan results) finds where one prescribed medicine's label names another.
  - **Alternatives** is one card: "Same dose" (`isEquivalent`: same ingredients, strength and form, i.e. the same medicine at another price, with the saving) and "Other strengths & forms", cheapest first. Detail cards are `_ExpandableCard`s with a `PageStorageKey`: the phone layout is a lazy `ListView`, and without the key a card the user closed reopened when scrolled back into view.

**Prescription pipeline ([lib/screens/analysis_screen.dart](lib/screens/analysis_screen.dart)):**
0. Every scan starts in `startPrescriptionScan` ([scan_flow.dart](lib/widgets/scan_flow.dart)): from the bar's Scan button, the rail or sidebar button, or the home card. With family members saved, or when no source was chosen yet, a sheet asks who the prescription is for (and can add someone) and camera or gallery. `AnalysisScreen(profileId:)` then works for that person.
1. OCR runs (ML Kit; skipped on web).
2. `AiHandwritingService` transcribes the image through `GeminiClient.generateJson` within a 100 s total budget (35 s per request), with a shorter recovery prompt when the first finds no lines. The prompt lists common Lebanese direction phrases and a plausibility rule: a word that cannot be part of a dosing direction is a misreading ("العفن" was really "على الريق"). The model must re-read it, or write `[?]` and require confirmation.
3. `MedicineVerificationService` matches the transcription to MOPH products. The strength comes from the product text, never the directions ("5 ml three times daily" is a dose). Forms are compared by family, and the route is implied by the MOPH form (the list has no route column).
4. `MedicationSafetyService` flags allergies (ingredient, ATC class, Arabic names, related chemical class), health conditions, duplicate ingredients and same-class pairs. All of these use the scan's person: their allergies and `effectiveConditions` (an age under 12 adds "child"). Possible matches get allergy and condition alerts worded "If this line is ...".
   - Condition alerts come from `_conditionRules`: (condition, ATC prefixes, group, effect). Examples: beta blockers with asthma, NSAIDs with kidney disease, ACE inhibitors and sartans in pregnancy. They are cautions that send the user to their doctor, never "safe" or "unsafe".
   - Pick ATC prefixes narrowly: R05DA also covers dextromethorphan, so codeine is R05DA04. A test checks that every rule matches products in the catalog.
   - The person's conditions that no rule covered, and conditions they typed ("Other…"), are listed in a "Health conditions to mention" card.
5. The scan is saved on the device by `PrescriptionHistoryService` under that person. "Change" on the analysis or the saved scan moves it (`updateProfile`). Medicine pages, `ForYouCard` and reminders opened from a scan get the same `profileId`.

A "possible" line opens a quick picker of the closest products before full search.

**AI notices:** wherever the app shows something an AI produced (the scan, its directions, summaries), show `AiNotice` ([ai_notice.dart](lib/widgets/ai_notice.dart)): AI can make mistakes; ask the pharmacist or doctor. The analysis loading and results screens, saved scans, the doctor's directions on medicine pages, the scan sheet and the home footer all have it.

The design rule is that **Gemini only transcribes**. Identity, prices and safety come from registry data.

**Gemini ([lib/services/gemini_client.dart](lib/services/gemini_client.dart)):** the one place for keys, model order, `generationConfig` and the model/key fallback loop (`send`, with a total time budget). Every Gemini call goes through it: `generateJson` (scan, medicine info) or `chatWithTools` (assistant). Errors arrive as `GeminiException` with a `GeminiErrorKind`. Gemini 3 models get `thinkingLevel: low` and no temperature: their default high thinking, or a temperature below 1.0, made scans slow or cut off (thinking tokens count toward `maxOutputTokens`). In a tool conversation the model's turns are sent back verbatim (Gemini 3 thought signatures) and later rounds stay on the model that answered first.

**Assistant ([lib/services/chatbot_service.dart](lib/services/chatbot_service.dart)):**
- Its instructions are [assets/chatbot/knowledge_notes.md](assets/chatbot/knowledge_notes.md), sent as `systemInstruction` with every message; edit them to change its behavior.
- Facts come from [ChatbotTools](lib/services/chatbot_tools.dart) (MOPH search, details, alternatives, safety check, the selected person's data, patient information, doctors, nearby pharmacies, dataset info). Prices only in LBP, as the tools return them; never from model memory.
- A photo goes through `AiHandwritingService` and `MedicineVerificationService` first; the model sees only the verified result.
- `MedicalDomainGuardService` runs first: crisis messages get Embrace 1564 and Red Cross 140, follow-ups in a health conversation are allowed.
- Answers are Markdown rendered by [MarkdownText](lib/widgets/markdown_text.dart) (no raw `**`), with an AI notice under each answer and pinned at the top.

**Reminders ([lib/services/reminder_service.dart](lib/services/reminder_service.dart)):**
- Modes: notification, or alarm (repeats until answered, full-screen intent). Android fixes a channel's sound at creation, so each alarm sound has its own channel: `medicine_alarms_v1` for the PharmaLens tone (`res/raw/pharmalens_alarm.wav`), `medicine_alarms_<md5>` for a chosen one; the old channel is deleted when the sound changes.
- **Alarm sound** ([AlarmSoundService](lib/services/alarm_sound_service.dart), [AlarmSound.kt](android/app/src/main/kotlin/com/techwraplb/pharmalens/AlarmSound.kt), `AlarmSoundTile` in the reminder editor and setup sheet; Android only): the phone's alarm-tone picker, or any audio file, which is copied into the shared `Alarms/PharmaLens` folder (Android 10+) because the notification system cannot read a file granted only to the app. The dose screen plays it natively (looping; it pauses for the spoken name) and falls back to the PharmaLens tone if the file is gone.
- An end date less than 14 days away gets one notification per dose, so reminders stop exactly; longer courses repeat daily and switch as the end nears. Ids are `reminder.id * 1000 + offset`; payloads are `dose:<id>:<minutes>[:<date>]`.
- Each add, edit or answer reschedules its own reminder. The full rebuild (`_rescheduleIfNeeded`) runs 3 s after launch and on resume, only when `_scheduleSignature` changed: every notification is a call on Android's UI thread, and rebuilding on every open froze the first screen. The time-zone database loads on first scheduling, not at launch.
  - The signature covers the reminders, language, alarm channel, exact-alarm permission, time zone and day.
  - It also covers the phone's boot time (channel `pharmalens/system`, `bootTime` in [MainActivity.kt](android/app/src/main/kotlin/com/techwraplb/pharmalens/MainActivity.kt)). Android clears every alarm on restart, so the first open after a reboot always rebuilds them, even when the plugin's boot receiver was blocked (no "Autostart" on Xiaomi, Tecno and similar phones).
- Taken / Snooze buttons work from the notification (`reminderBackgroundResponse`, a background isolate) and are logged by `DoseLogService` (adherence, home progress). A tap, an alarm, or a due alarm while the app is open sets `pendingDose`, and the shell opens [DoseScreen](lib/screens/dose_screen.dart) (tone plus spoken name via `flutter_tts`).
- Only a `dose:` launch may show the app over the lock screen ([MainActivity.kt](android/app/src/main/kotlin/com/techwraplb/pharmalens/MainActivity.kt)); the dose screen turns it off on close.
- Permissions: [ReminderPermissions](lib/services/reminder_permissions.dart) and `showReminderSetupSheet` (notifications, exact alarms, full-screen, battery). Shown in onboarding, offered again by `ensureReminderSetup` whenever a reminder is saved without what it needs. "Display over other apps" is not used.
- The course length is read from the directions (`courseDaysFrom`); refill dates come from `packUnits`, `unitsPerDose` and the times.

**On-device user data:** `PrescriptionHistoryService` (up to 200 scans; photos are copied to app storage and decoded at display size), `ReminderService`, `DoseLogService` and `HealthProfileService`. The last holds family profiles. Each person has allergies, conditions (`HealthCondition`, stored by name, so add new values at the end), conditions typed with "Other…" (`otherConditions`), and age (stored as a birth year), sex, height and weight. `allergies` and `conditions` on the service are the selected person's. My Health shows the BMI on a WHO scale, with obesity classes I to III. The shared add-person and add-condition dialogs are in [family_member_dialog.dart](lib/widgets/family_member_dialog.dart). My Health lists prescriptions and reminders a page at a time (`_Paged`), and `MyHealthScreen.requestedTab` opens a tab (Home's "Show all"). Dialogs with a text field own their controller in a `State` (`_NameDialog`): disposing it right after `showDialog` returns crashes while the dialog fades out. Reminders and prescriptions carry a `profileId` ("me" for the owner). These are `ChangeNotifier` singletons that the UI listens to with `ListenableBuilder`. `SpeechService` is one too: read aloud toggles play/pause, and resumes from the last word the engine reported. `MedicationListService` shares a person's list as text.

**Map ([lib/widgets/universal_map_view.dart](lib/widgets/universal_map_view.dart)):** one OpenStreetMap view on every platform (touch pan/pinch/double-tap, buttons, markers), no key or billing. `google_maps_flutter` was removed. Its blank map with only a "Google" logo was the key, not the code: checked on 2026-10-30, Google answered `API_KEY_ANDROID_APP_BLOCKED` for the old package `com.codepeakstudio.pharmalens`, because the key's Android restriction didn't list this package and signing certificate (that key was also in public history). A blank map like that now means an old build is installed. CARTO's keyless tiles return a watermark; OSM's tile policy fits light use, so switch to a tile provider before heavy traffic. The map's search box narrows the shown pharmacies as the user types; Enter calls `NearbyHealthcareService.searchPharmacies` (Places Text Search, pharmacies only, across Lebanon, biased toward the user), and clearing it returns to the nearby list.

**Emergency numbers** ([emergency_numbers.dart](lib/widgets/emergency_numbers.dart)): Red Cross 140, Civil Defense 125, ISF 112, fire 175, Embrace 1564 and the MOPH hotline 1214. They appear as a home card and in Settings.

**Brand:** [tools/generate_brand_assets.py](tools/generate_brand_assets.py) draws the logo (a pharmacy cross with the bowl of Hygieia, framed by camera scan corners, with AI sparkles) and writes every launcher icon (Android adaptive and themed, iOS, macOS, web, Windows), the splash logo and `assets/images/*` illustrations. Edit colors there, not in the PNGs. iOS alarms play `ios/Runner/pharmalens_alarm.wav` (a copy of the Android raw tone, listed in the Xcode project's resources).

## Localization

ARB files live in `lib/l10n/` with `app_en.arb` as the template; run `flutter gen-l10n` after editing them. The generated files are committed. Add every new string to both ARB files and read it with `context.l10n.<key>`, or with `appText(isArabic).<key>` ([app_text.dart](lib/l10n/app_text.dart)) where code has a language flag but no context (services, models, notifications). Values go in as placeholders (`"{count} medicines"`). Don't add new inline `isArabic ? 'ar' : 'en'` pairs. The few left are deliberate: English and Arabic take different values, or the text is a name rather than a translation. [test/sync_and_l10n_test.dart](test/sync_and_l10n_test.dart) checks that both files have the same keys and placeholders.

## Theming

The app opens in light mode until the user picks another theme in Settings. Don't make it follow the system by default, and Android's night `NormalTheme` is light too. Use `PharmaLensTheme.paletteOf(context)`, `PharmaLensColors`, `PharmaLensDecorations` and the shared widgets in `responsive.dart`, not raw colors. Colors used outside the theme have names there too (`brandGradient`, the `accent*` feature colors, map colors, other brands' marks); add new ones there rather than writing `Color(0x...)` in a screen. Every screen must work in light and dark mode, in RTL, at phone, tablet and desktop widths, and with text up to 1.6× (the app's cap). [test/app_shell_test.dart](test/app_shell_test.dart) and [test/new_screens_test.dart](test/new_screens_test.dart) fail on layout overflow. Avoid endless animations on pages tests pump to settle.

## Conventions

- Older files use a very vertical formatting style that does not match `dart format`. Match the style of the file you're editing and don't reformat whole files. New files use normal Dart formatting.
- Log errors through a local `_debugLog` or `debugPrint`, and show users friendly messages only.
- `showGeneralDialog` adds no `Material` ancestor (bottom sheets do): wrap its content in `Material(type: MaterialType.transparency)`. The same applies to an `ExpansionTile`/`ListTile` placed directly on a colored box.
- The pubspec SDK floor is `>=3.0.0`, so wildcard `_` parameters can't be repeated. Name them (`context, error, stackTrace`).
- Regex word boundaries are `\b` in a raw string. A literal backspace character (U+0008) in its place once silently broke two regexes; editing through shell heredocs can produce one.
- A `Flexible`/`Expanded` inside a vertical scroll view has no height to share and renders nothing in release builds; use a plain `Column` there.
- [medicine_details_screen.dart](lib/screens/medicine_details_screen.dart) holds the screen and its state; its cards live in `part` files under [lib/screens/medicine_details/](lib/screens/medicine_details/) (overview, prices and sources, shared building blocks, text helpers). Imports go in the main file only.
- Scripts that rewrite Dart files must keep each file's line endings (most are CRLF); open them in binary or with `newline=''`.
